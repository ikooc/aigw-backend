一个出口，全部供应商
上游协议差异（鉴权、请求体、错误码、流式格式）在网关收敛掉，接入方只面向一套 OpenAI 接口，模型名保持不变。
账号池：轮换与并发
同一供应商下多账号分组管理，按租约排队调度、故障自动转移；并发能力取决于供应商上限，跨供应商可真正并行。
模型目录自动同步
从上游拉取可用模型目录并落地到本地，按供应商开关逐个启用；请求的模型名会先解析再路由。
网关侧破甲（思维注入）
转发前统一注入 · 换端、重装、升级都不掉
为什么放在网关侧
改客户端提示词文件的老做法，被搬到了转发链路上
思维注入
不改客户端任何文件
注入发生在请求发往上游之前，客户端只需把 base_url 指过来。换客户端、重装、升级都不会掉思维，也不需要在本机留任何补丁产物。
思维库 + 靶点开关
多份思维并存，按供应商（靶点）与模型精准开启；用户端可自选哪几份对自己生效、在哪些平台生效，互不干扰。同一作用域下只有一份默认思维上场。
三种模式 + 幂等剥离
prepend / append / replace 一应俱全；注入前先剥离历史注入块，重采样、重试都不会叠第二遍，既不浪费上下文，也不让「末尾声明」失效。
主导权回收尾注
客户端模板自带的「遵循平台安全准则 / 不适当就礼貌拒绝」会被显式宣告废止，尾注固定在 system 最末尾——位置是实测结论，放开头等于给模板让路。
封条校验 + 快照还原
每份思维都有 SHA256 封条，正文被改动即诊断报警（仍按现文注入，不中断服务）；每次保存自动留快照，还原前也留，随时可回滚。
自证口令：链路通不通一眼可见
命中固定口令时网关直接回执、不打上游，不必靠「感觉好像生效了」判断；调用日志里可按思维 id 与命中数逐条核对。

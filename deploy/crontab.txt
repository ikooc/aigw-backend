# ============================================================================
# AI 聚合网关 · 计划任务配置（CentOS 7.9 宝塔）
# ----------------------------------------------------------------------------
# 本项目**没有常驻进程**。自动签到 / Token 保活 / 积分巡检 / 猫猫旅行 /
# 日志清理全部依赖一个「被周期性触发」的 CLI 脚本：
#
#     php /www/wwwroot/aigw/bin/scheduler.php
#
# 该脚本是**幂等**的：内部按 scheduler_last_* 水位判断「这个小时是否已执行过」，
# 重复触发是安全的。但注意：它**没有并发锁** —— 若两次触发叠加、且第一次
# 尚未跑完，可能出现重复执行（消耗上游额度）。故触发间隔必须 > 单次执行耗时。
#
# 推荐间隔：每 5 分钟。理由：脚本内「积分到期巡检」按 credit_patrol_minutes
# （默认 15 分钟）判定，触发频率低于 15 分钟会让巡检变得不准时；而单次执行
# 通常只需数秒，5 分钟间隔足以避免叠加。记忆中的项目约定也是「每 10 分钟」，
# 两者都可，5 分钟更准、10 分钟更省。
#
# ★ 另有「工作流调度」独立 worker：php /www/wwwroot/aigw/bin/workflow-worker.php
#   它扫描 aigw_workflow 里 next_run_at 到期的用户工作流并按图执行。与 scheduler
#   相互独立：scheduler 管内置签到/保活等，workflow-worker 管用户自定义工作流。
#   建议间隔：每 1 分钟（工作流最小周期 15 分钟，1 分钟触发保证准点、且执行幂等）。
# ============================================================================

# ---------------------------------------------------------------------------
# 方案 A（推荐）：宝塔面板 → 计划任务
# ---------------------------------------------------------------------------
# 类型：Shell 脚本
# 名称：AI网关-调度器
# 周期：N 分钟 → 5 分钟
# 脚本内容（直接粘贴）：
#
#     cd /www/wwwroot/aigw && /www/server/php/82/bin/php bin/scheduler.php
#
# ⚠️ 用**绝对路径**调 php：宝塔的定时任务运行环境 PATH 与登录 shell 不同，
#    直接写 `php` 可能找不到，或误用系统自带的 PHP 5.4（CentOS 7 默认带）。
#
# ⚠️ 若需要「ZCode 领额度」相关能力，注意计划任务环境需能访问 Node：
#     cd /www/wwwroot/aigw && AIGW_NODE_BIN=/usr/bin/node /www/server/php/82/bin/php bin/scheduler.php

# ---------------------------------------------------------------------------
# 方案 B：系统 crontab
# ---------------------------------------------------------------------------
# 执行：crontab -e
# 粘贴（把 PHP 路径换成 `ls /www/server/php/*/bin/php` 得到的实际值）：
#
#     */5 * * * * cd /www/wwwroot/aigw && /www/server/php/82/bin/php bin/scheduler.php >> /www/wwwroot/aigw/storage/logs/cron.log 2>&1
#     * * * * * cd /www/wwwroot/aigw && /www/server/php/82/bin/php bin/workflow-worker.php >> /www/wwwroot/aigw/storage/logs/cron.log 2>&1

# ---------------------------------------------------------------------------
# 验证是否生效
# ---------------------------------------------------------------------------
# 1) 手动执行一次，应看到输出（不是报错）：
#        cd /www/wwwroot/aigw && /www/server/php/82/bin/php bin/scheduler.php
#    期望输出形如：
#        [scheduler] 已跳过：定时任务未启用（...）      ← 说明能跑，只是开关没开
#        [scheduler] 已执行：...                        ← 说明有任务到点并执行了
#
# 2) 看日志：
#        tail -f /www/wwwroot/aigw/storage/logs/app-$(date +%F).log
#
# 3) 看管理台：管理后台 → 定时任务卡片，会显示「上次执行时间」。
#
# 注意：任务总开关（自动签到 / Token 保活 / 猫猫旅行 / 每日活跃 / 成长中心领奖）
#       在管理台「设置」里，**默认是关闭的**。脚本能正常执行但「已跳过」属正常现象。
#       想让它真正干活，去管理台把对应开关打开。

# ---------------------------------------------------------------------------
# ★ CentOS 7 特有注意事项
# ---------------------------------------------------------------------------
# 1) CentOS 7 自带的 crond 默认是启用的；若你用了宝塔的「计划任务」则无需管 crond。
#
# 2) MySQL 连接超时：脚本内有几十次数据库往返，若 MySQL 的 wait_timeout 很小、
#    或脚本中途长时间等待上游，MySQL 可能已把连接掐断，报 "MySQL server has gone away"。
#    本项目已在长脚本里做过 wait_timeout 处理；若仍在 cron.log 里看到该报错，
#    在 MySQL 配置里把 wait_timeout 调到 600+（宝塔 → 数据库 → 性能调整）。
#
# 3) 时区：cron 用的是**系统时区**，而脚本内的签到/保活判定用 date()（PHP 时区）。
#    两者必须都是 Asia/Shanghai，否则会出现「22 点该保活却没跑」。
#    检查：
#        timedatectl                      # 系统时区
#        php -r 'echo date_default_timezone_get();'   # PHP 时区
#    若系统时区不对：
#        timedatectl set-timezone Asia/Shanghai
#
# 4) SELinux：CentOS 7 默认可能开着 enforcing，会阻止 php-fpm / cron 写 storage。
#    若遇到莫名其妙的「写入失败」，检查：
#        getenforce
#    返回 Enforcing 且确认是它导致的话，可临时 setenforce 0 验证（生产请用
#    正确的 SELinux 策略，而不是长期关闭）。
